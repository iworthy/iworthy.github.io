Java 8 的 Stream API 可以把 List 的过滤、转换、排序、分组和统计写成连续的数据处理步骤。例如，从员工列表中找出研发部门的成员，按工资倒序取前两名，再提取姓名，整个过程可以在一条流水线里表达清楚。

本文以 **Java 8** 为版本边界，围绕 `List.stream()` 展开，覆盖 `Stream<T>` 的全部操作方法、继承自 `BaseStream` 的控制方法、Java 8 的收集器家族，以及数值流、空值处理和业务组合用法。示例只使用 JDK 标准库，不依赖 Lombok 或第三方工具包。

## 一、先运行一个完整示例

将下面代码保存为 `ListStreamDemo.java`。后文的 Java 片段默认使用这里的 import、`User` 类和 `sampleUsers()`；可以放进 `main` 中分别运行，每次示例开始时重新执行 `List<User> users = sampleUsers();`。同名变量所在的不同片段应分开执行。

```java
import java.math.BigDecimal;
import java.util.*;
import java.util.concurrent.ConcurrentMap;
import java.util.function.*;
import java.util.stream.*;

public class ListStreamDemo {
    static final class User {
        private final Long id;
        private final String name;
        private final int age;
        private final String department;
        private final BigDecimal salary;
        private final List<String> skills;

        User(Long id, String name, int age, String department,
             BigDecimal salary, List<String> skills) {
            this.id = id;
            this.name = name;
            this.age = age;
            this.department = department;
            this.salary = salary;
            this.skills = skills;
        }

        public Long getId() { return id; }
        public String getName() { return name; }
        public int getAge() { return age; }
        public String getDepartment() { return department; }
        public BigDecimal getSalary() { return salary; }
        public List<String> getSkills() { return skills; }

        @Override
        public String toString() {
            return name + "(" + age + ", " + department + ")";
        }
    }

    static List<User> sampleUsers() {
        return new ArrayList<>(Arrays.asList(
                new User(1L, "张三", 28, "研发", new BigDecimal("18000"),
                        Arrays.asList("Java", "SQL")),
                new User(2L, "李四", 32, "研发", new BigDecimal("22000"),
                        Arrays.asList("Java", "Docker")),
                new User(3L, "王五", 24, "测试", new BigDecimal("12000"),
                        Arrays.asList("Testing", "SQL")),
                new User(4L, "赵六", 35, "产品", new BigDecimal("20000"),
                        Arrays.asList("Design")),
                new User(5L, "孙七", 28, "测试", new BigDecimal("15000"),
                        Arrays.asList("Java", "Testing"))
        ));
    }

    public static void main(String[] args) {
        List<User> users = sampleUsers();
        List<String> names = users.stream()
                .filter(u -> "研发".equals(u.getDepartment()))
                .sorted(Comparator.comparing(User::getSalary).reversed())
                .limit(2)
                .map(User::getName)
                .collect(Collectors.toList());

        System.out.println(names); // [李四, 张三]
    }
}
```

## 二、Stream 的工作方式

### 2.1 数据源、中间操作、终止操作

```text
List<User>
  → stream()                 创建流
  → filter(...)              中间操作：筛选员工
  → sorted(...)              中间操作：排序
  → map(...)                 中间操作：提取姓名
  → collect(...)             终止操作：收集结果
```

中间操作通常返回另一个流；终止操作返回集合、数值、`Optional`，或者执行遍历。中间操作具有惰性，只拼装流水线，不立即处理元素。直到终止操作执行，流水线才开始消费数据。完整规则见 [Java 8 Stream 包文档](https://docs.oracle.com/javase/8/docs/api/java/util/stream/package-summary.html)。

```java
Stream<User> pipeline = users.stream()
        .filter(u -> {
            System.out.println("检查：" + u.getName());
            return u.getAge() >= 30;
        });

System.out.println("流水线已创建");
List<User> result = pipeline.collect(Collectors.toList());
// 先输出“流水线已创建”，再输出逐个检查的日志。
```

### 2.2 流只能消费一次

终止操作之后，要从 List 重新创建流。不要把 `Stream` 当作可多次查询的集合保存。

```java
long count = users.stream().count();
Optional<User> first = users.stream().findFirst();
// 两次查询分别创建一个流，合法。
```

下面是错误写法，注释中的第二次消费会抛出 `IllegalStateException`：

```java
Stream<User> stream = users.stream();
long count = stream.count();
// stream.findFirst(); // 错误：stream 已经被消费。
```

### 2.3 新 List 不代表深拷贝

`filter`、`sorted`、`map` 本身不会删除或重排原 List 的元素；但 Lambda 可以引入修改，收集结果也可能仍引用原对象。

```java
List<User> selected = users.stream()
        .filter(u -> u.getAge() >= 30)
        .collect(Collectors.toList());

System.out.println(selected.get(0) == users.get(1)); // true
```

如果实际业务类有 setter，修改 `selected` 内对象的属性也可能影响原列表中看到的对象。需要隔离对象时，应在 `map` 中构造新的 DTO 或副本。

### 2.4 Lambda 和方法引用速查

| 函数接口 | 含义 | 例子 | 常见位置 |
| --- | --- | --- | --- |
| `Predicate<T>` | 输入 T，返回 boolean | `u -> u.getAge() >= 30` | `filter`、`anyMatch` |
| `Function<T, R>` | 输入 T，返回 R | `User::getName` | `map`、`toMap` |
| `Consumer<T>` | 消费 T，无返回值 | `System.out::println` | `forEach`、`peek` |
| `Supplier<T>` | 无参数，创建 T | `ArrayList::new` | `collect`、`generate` |
| `BinaryOperator<T>` | 两个 T 合成一个 T | `BigDecimal::add` | `reduce`、合并重复 key |
| `Comparator<T>` | 比较两个 T | `Comparator.comparingInt(User::getAge)` | `sorted`、`max` |

`User::getName` 在这里相当于 `u -> u.getName()`；`Function.identity()` 相当于 `u -> u`。

## 三、创建流：不止 list.stream()

```java
Stream<User> sequential = users.stream();
Stream<User> parallel = users.parallelStream();

Stream<String> fromValues = Stream.of("Java", "SQL", "Docker");
Stream<String> fromArray = Arrays.stream(new String[]{"A", "B"});
Stream<String> empty = Stream.empty();

Stream<String> built = Stream.<String>builder()
        .add("Java").add("SQL").build();

List<Integer> oddNumbers = Stream.iterate(1, n -> n + 2)
        .limit(5)
        .collect(Collectors.toList()); // [1, 3, 5, 7, 9]

List<String> repeated = Stream.generate(() -> "Java")
        .limit(3)
        .collect(Collectors.toList()); // [Java, Java, Java]
```

Java 8 的 `iterate(seed, next)` 和 `generate(supplier)` 创建无限流。有限结果通常需要先 `limit`，再收集；不要对未限制的无限流直接 `collect` 或 `sorted`。`generate` 创建的流不提供遭遇顺序保证，生成函数也应遵守无状态等约束。

`Stream.of(intArray)` 得到的是包含一个数组的 `Stream<int[]>`；若需要处理数组里的整数，应使用 `Arrays.stream(intArray)` 得到 `IntStream`。

空引用和空集合是两回事：

```java
List<User> nullableUsers = null;
Stream<User> safeStream = Optional.ofNullable(nullableUsers)
        .orElseGet(Collections::emptyList)
        .stream();

System.out.println(safeStream.count()); // 0
```

## 四、filter：过滤与条件组合

```java
List<User> adults = users.stream()
        .filter(u -> u.getAge() >= 30)
        .collect(Collectors.toList()); // 李四、赵六

List<User> developers = users.stream()
        .filter(u -> "研发".equals(u.getDepartment()))
        .filter(u -> u.getAge() >= 30)
        .collect(Collectors.toList()); // 李四

List<User> selected = users.stream()
        .filter(u -> "研发".equals(u.getDepartment()) || u.getAge() < 25)
        .collect(Collectors.toList()); // 张三、李四、王五
```

连续两个 `filter` 表示“并且”；“或者”应在同一个条件中用 `||`，也可以组合 `Predicate`：

```java
Predicate<User> inDevelopment = u -> "研发".equals(u.getDepartment());
Predicate<User> ageAtLeast30 = u -> u.getAge() >= 30;

List<User> result = users.stream()
        .filter(inDevelopment.and(ageAtLeast30).negate())
        .collect(Collectors.toList()); // 除李四外的其他人
```

如果 List 里可能有 `null` 元素，先过滤对象，再读取属性：

```java
List<String> names = users.stream()
        .filter(Objects::nonNull)
        .map(User::getName)
        .filter(Objects::nonNull)
        .map(String::trim)
        .filter(s -> !s.isEmpty())
        .collect(Collectors.toList());
```

这里处理了“对象为空”和“字段为空”两个层次。Java 8 没有 `String.isBlank()`，如果业务对 Unicode 空白有更严格要求，还需要单独定义判定规则。

## 五、map 与 flatMap：转换、提取和展开

### 5.1 map：一个元素映射为一个结果

```java
List<String> names = users.stream()
        .map(User::getName)
        .collect(Collectors.toList());

List<Integer> ages = users.stream()
        .map(User::getAge)
        .collect(Collectors.toList());

List<String> labels = users.stream()
        .map(u -> u.getName() + " / " + u.getDepartment())
        .collect(Collectors.toList());
```

`map` 不自动剔除 `null` 返回值。DTO 转换时可以写 `.map(u -> new UserDTO(...))`，需要哪些字段就在转换时明确列出。

### 5.2 flatMap：一个元素展开成零个或多个结果

`map(User::getSkills)` 得到 `Stream<List<String>>`；`flatMap` 会把每个人的技能流接起来，得到 `Stream<String>`。

```java
List<String> skills = users.stream()
        .map(User::getSkills)
        .filter(Objects::nonNull)
        .flatMap(Collection::stream)
        .filter(Objects::nonNull)
        .distinct()
        .sorted()
        .collect(Collectors.toList());
// [Design, Docker, Java, SQL, Testing]
```

拆分多个字符串也一样：

```java
List<String> words = Arrays.asList("Java,SQL", "Docker,Java").stream()
        .flatMap(s -> Arrays.stream(s.split(",")))
        .map(String::trim)
        .filter(s -> !s.isEmpty())
        .distinct()
        .collect(Collectors.toList()); // [Java, SQL, Docker]
```

Java 8 的 `flatMapToInt`、`flatMapToLong`、`flatMapToDouble` 则直接展开成基本类型流：

```java
int[] values = Arrays.asList(new int[]{1, 2}, new int[]{3, 4}).stream()
        .flatMapToInt(a -> Arrays.stream(a))
        .toArray(); // [1, 2, 3, 4]

long total = Stream.of(new long[]{10L, 20L}, new long[]{30L})
        .flatMapToLong(a -> Arrays.stream(a))
        .sum(); // 60

double sum = Stream.of(new double[]{1.5}, new double[]{2.5})
        .flatMapToDouble(a -> Arrays.stream(a))
        .sum(); // 4.0
```

## 六、distinct：去重，以及按字段去重

### 6.1 普通元素去重

```java
List<Integer> numbers = Arrays.asList(3, 1, 3, 2, 1);
List<Integer> unique = numbers.stream()
        .distinct()
        .collect(Collectors.toList()); // [3, 1, 2]
```

`distinct()` 使用元素的 `equals` 判等，重写实体类时也要正确实现 `hashCode`。对于 List 这样的有序数据源，去重保留最先出现的相等元素。

本文的 `User` 没有重写这两个方法，所以两个字段相同、但分别 `new` 出来的 User 仍会被视为不同对象。不要把 `.distinct()` 理解成“自动按 ID 去重”。

### 6.2 按 ID 去重，并保留第一次出现的对象

```java
List<User> duplicated = new ArrayList<>(users);
duplicated.add(new User(1L, "张三的新记录", 29, "研发",
        new BigDecimal("19000"), Arrays.asList("Java")));

List<User> uniqueById = new ArrayList<>(duplicated.stream()
        .collect(Collectors.toMap(
                User::getId,
                Function.identity(),
                (first, later) -> first,
                LinkedHashMap::new
        ))
        .values());
// 共 5 人；ID=1 保留张三的第一条记录，结果按 key 首次出现的顺序排列。
```

改成 `(first, later) -> later` 可保留后出现的值；`LinkedHashMap` 中已有 key 的位置不会因此移到末尾。若重复 ID 意味着业务数据异常，应保留异常或显式校验，不能随意丢弃记录。

网上常见的 `filter(distinctByKey(...))` 往往通过外部 Set 保存已见过的 key，属于有状态条件，在并行执行时容易引入顺序语义问题。用 `toMap` 明确冲突规则通常更容易审查。

## 七、sorted：自然排序、多字段排序和 null

```java
List<Integer> ascending = Arrays.asList(3, 1, 2).stream()
        .sorted()
        .collect(Collectors.toList()); // [1, 2, 3]

List<User> byAge = users.stream()
        .sorted(Comparator.comparingInt(User::getAge))
        .collect(Collectors.toList());

List<User> bySalaryDesc = users.stream()
        .sorted(Comparator.comparing(User::getSalary).reversed())
        .collect(Collectors.toList());
```

不传比较器的 `sorted()` 要求元素能够自然比较；本文 `User` 没有实现 `Comparable`，应传入比较器。

### 7.1 年龄升序，同龄工资降序，最后按 ID 升序

```java
Comparator<User> order = Comparator.comparingInt(User::getAge)
        .thenComparing(Comparator.comparing(User::getSalary).reversed())
        .thenComparing(User::getId);

List<User> sorted = users.stream()
        .sorted(order)
        .collect(Collectors.toList());
// 王五、张三、孙七、李四、赵六
```

`reversed()` 反转它所作用的整个比较器。如果在整条链末尾调用，就会把前面全部排序条件一起反转；只想倒序某一个字段时，应像上面那样单独构造该字段的比较器。

不要用 `a.getAge() - b.getAge()` 编写通用整数比较器，减法可能溢出；使用 `Integer.compare` 或 `comparingInt`。

### 7.2 对象为空和字段为空要分别处理

```java
Comparator<User> byNullableName = Comparator.comparing(
        User::getName,
        Comparator.nullsLast(Comparator.naturalOrder())
);

List<User> sorted = users.stream()
        .sorted(Comparator.nullsLast(byNullableName))
        .collect(Collectors.toList());
```

里面的 `nullsLast` 处理姓名为空；外面的处理 User 本身为空。如果要“倒序且 null 仍放最后”，应使用 `nullsLast(reverseOrder())` 作为字段比较器；把整个 `nullsLast(...)` 再反转会让 null 跑到前面。

有序流的排序是稳定的：比较结果相同的元素维持原有相对顺序。字符串自然顺序按字符编码比较，需要中文拼音顺序时应明确使用适合业务的比较规则。

## 八、limit 与 skip：截取、Top N 和内存分页

```java
List<User> firstTwo = users.stream()
        .limit(2)
        .collect(Collectors.toList()); // 张三、李四

List<User> afterTwo = users.stream()
        .skip(2)
        .collect(Collectors.toList()); // 王五、赵六、孙七

List<User> topTwo = users.stream()
        .sorted(Comparator.comparing(User::getSalary).reversed())
        .limit(2)
        .collect(Collectors.toList()); // 李四、赵六
```

`limit(n)` 最多保留 n 个；`skip(n)` 跳过前 n 个。n 为 0 合法，为负数会抛出 `IllegalArgumentException`；跳过的数量大于元素数时，结果为空。

分页前通常需要明确排序，且给相同排序值补充稳定的次级条件：

```java
int pageNo = 2;   // 从 1 开始
int pageSize = 2;
if (pageNo < 1 || pageSize < 1) {
    throw new IllegalArgumentException("页码和每页数量必须大于 0");
}
long offset = ((long) pageNo - 1) * pageSize;

List<User> page = users.stream()
        .sorted(Comparator.comparing(User::getId))
        .skip(offset)
        .limit(pageSize)
        .collect(Collectors.toList()); // 王五、赵六
```

先转换成 `long` 再乘法，避免 int 中间结果溢出。大量数据库数据应在查询端分页；先查出全部数据再用 Stream 分页，仍然承担全量加载和排序成本。

操作顺序会改变含义：`sorted(...).limit(2)` 是全体中的前两名；`limit(2).sorted(...)` 只会重排原列表的前两项。

## 九、查找与匹配：findFirst、findAny 和 Match

### 9.1 找一个元素

```java
Optional<User> firstDeveloper = users.stream()
        .filter(u -> "研发".equals(u.getDepartment()))
        .findFirst(); // 张三

Optional<User> anyDeveloper = users.parallelStream()
        .filter(u -> "研发".equals(u.getDepartment()))
        .findAny(); // 任意一名研发成员
```

List 有遭遇顺序，`findFirst()` 按当前流水线顺序取第一个；如果之前排序过，就是排序后的第一个。`findAny()` 不保证每次选中同一项，适用于只关心“有没有任意一个”的场景。

两者都是短路终止操作，满足条件后可提前结束，但并行执行不保证只计算到精确的那个元素为止。若流中可能出现 null，先过滤再查找；选中 null 时不能把它包装成 `Optional`。

### 9.2 正确处理 Optional

```java
Optional<User> found = users.stream()
        .filter(u -> u.getId().equals(99L))
        .findFirst();

String name = found.map(User::getName).orElse("未找到");
User fallback = found.orElseGet(() -> users.get(0));
found.ifPresent(u -> System.out.println(u.getName()));

User required = users.stream()
        .filter(u -> u.getId().equals(1L))
        .findFirst()
        .orElseThrow(() -> new IllegalArgumentException("用户不存在"));
```

`get()` 在没有值时抛出异常。`orElse(expensiveCall())` 会先计算参数，即使已经有值；`orElseGet(() -> expensiveCall())` 只在没有值时计算。Java 8 必须给 `orElseThrow` 提供异常 Supplier。详见 [Optional 文档](https://docs.oracle.com/javase/8/docs/api/java/util/Optional.html)。

### 9.3 判断是否满足条件

```java
boolean hasDeveloper = users.stream()
        .anyMatch(u -> "研发".equals(u.getDepartment())); // true

boolean allAdults = users.stream()
        .allMatch(u -> u.getAge() >= 18); // true

boolean noMinor = users.stream()
        .noneMatch(u -> u.getAge() < 18); // true
```

| 操作 | 含义 | 空流结果 |
| --- | --- | --- |
| `anyMatch` | 至少一个满足条件 | `false` |
| `allMatch` | 所有元素都满足条件 | `true` |
| `noneMatch` | 没有元素满足条件 | `true` |

如果业务要求“列表非空且全部通过”，要另外判断非空；空流的 `allMatch` 为 true 并不代表存在任何一条记录。

判断是否存在时，优先使用 `anyMatch`，无需先过滤再 `count() > 0`，也无需收集出整个临时列表。

## 十、计数、极值与数值流

### 10.1 count、min 和 max

```java
long count = users.stream().count(); // 5，返回 long
long developers = users.stream()
        .filter(u -> "研发".equals(u.getDepartment()))
        .count(); // 2

Optional<User> youngest = users.stream()
        .min(Comparator.comparingInt(User::getAge)); // 王五

Optional<User> highestPaid = users.stream()
        .max(Comparator.comparing(User::getSalary)); // 李四
```

只要最大、最小元素时，直接 `max`、`min`，避免为了取一个值先完整排序。空流得到 `Optional.empty()`；如果多个元素比较结果相同，需要固定选谁，就把 ID 等条件写进比较器。

### 10.2 mapToInt、mapToLong、mapToDouble

```java
int ageSum = users.stream().mapToInt(User::getAge).sum(); // 147
double ageAverage = users.stream()
        .mapToInt(User::getAge)
        .average()
        .orElse(0.0); // 29.4

OptionalInt maxAge = users.stream().mapToInt(User::getAge).max(); // 35
long ageSumAsLong = users.stream()
        .mapToLong(u -> (long) u.getAge())
        .sum(); // 147

double halfAgeSum = users.stream()
        .mapToDouble(u -> u.getAge() / 2.0)
        .sum(); // 73.5
```

`IntStream`、`LongStream`、`DoubleStream` 对基本类型提供专用操作，减少装箱；`average()` 返回 `OptionalDouble`，`IntStream.min/max` 返回 `OptionalInt`，Long 和 Double 有对应的 Optional 类型。

空数值流的 `sum()` 为 0，`average/min/max` 为空。int 求和仍可能溢出；应按范围选择 long 或更大的数值类型。double 存在浮点舍入误差，金额通常用 `BigDecimal`。参见 [IntStream 文档](https://docs.oracle.com/javase/8/docs/api/java/util/stream/IntStream.html)。

### 10.3 一次遍历得到多项统计

```java
IntSummaryStatistics stats = users.stream()
        .mapToInt(User::getAge)
        .summaryStatistics();

System.out.println(stats.getCount());   // 5
System.out.println(stats.getSum());     // 147
System.out.println(stats.getMin());     // 24
System.out.println(stats.getMax());     // 35
System.out.println(stats.getAverage()); // 29.4
```

空流时，`getCount()` 为 0、`getSum()` 为 0、`getAverage()` 为 0；Int 统计的 min/max 是边界哨兵值 `Integer.MAX_VALUE` / `Integer.MIN_VALUE`。显示极值前先判断 `getCount() > 0`。Long 使用 long 边界，Double 使用正、负无穷作为空统计的极值。

### 10.4 boxed、mapToObj、范围和类型转换

```java
List<Integer> oneToFive = IntStream.rangeClosed(1, 5)
        .boxed()
        .collect(Collectors.toList()); // [1, 2, 3, 4, 5]

List<String> labels = IntStream.range(0, users.size())
        .mapToObj(i -> i + ":" + users.get(i).getName())
        .collect(Collectors.toList());

long[] longs = IntStream.of(1, 2, 3).asLongStream().toArray();
double[] doubles = IntStream.of(1, 2, 3).asDoubleStream().toArray();
```

`range(a, b)` 包含 a、不包含 b；`rangeClosed(a, b)` 两端都包含。`boxed()` 转为包装类型流，`mapToObj` 转为任意对象流。上面的索引访问适用于 `ArrayList`；对 `LinkedList` 反复 `get(i)` 可能产生明显性能开销。

三个基本类型流都支持过滤、映射、展开、去重、排序、截取、查找、匹配、遍历、归约、统计、数组和收集。它们的 `collect` 使用 supplier/accumulator/combiner 三参数形式；要使用 `Collectors`，可以先 `boxed()`。范围生成方法属于 IntStream 和 LongStream；`asLongStream` 属于 IntStream，`asDoubleStream` 属于 IntStream 和 LongStream。

## 十一、reduce：把多个元素归约为一个值

### 11.1 三种重载

```java
List<Integer> numbers = Arrays.asList(1, 2, 3, 4);

// 1. 无初始值：空流返回 Optional.empty()
Optional<Integer> sum1 = numbers.stream().reduce(Integer::sum); // 10

// 2. 有单位值：空流返回单位值
int sum2 = numbers.stream().reduce(0, Integer::sum); // 10

// 3. 结果类型可以不同于元素类型，第三个参数合并部分结果
int ageSum = users.parallelStream().reduce(
        0,
        (sum, user) -> sum + user.getAge(),
        Integer::sum
); // 147
```

三参数形式包含：单位值、把元素累积进结果的函数、合并部分结果的函数。单纯求年龄总和，`mapToInt(User::getAge).sum()` 更直观。

### 11.2 BigDecimal 金额求和

```java
BigDecimal salaryTotal = users.stream()
        .map(User::getSalary)
        .filter(Objects::nonNull)
        .reduce(BigDecimal.ZERO, BigDecimal::add); // 87000
```

这里把空工资排除，相当于不计入总额；真实业务也可能要求遇到空值直接报错。金额从十进制文本构造可以避免先经过 double 的误差，例如 `new BigDecimal("0.1")`。

### 11.3 单位值、结合律和合并兼容性

求和的单位值是 0，求积的单位值是 1。把 `reduce(10, Integer::sum)` 当作“最后再加 10”是不正确的归约约定：并行分段会分别使用这个值。应先按正确单位值归约，再对最终结果加 10。

累积和合并还要满足结合律。减法不满足 `(a - b) - c == a - (b - c)`，不适合做可并行归约。三参数形式的 combiner 必须与 accumulator 兼容，不能随意填写一个只为通过编译的函数。[Stream.reduce 的约束](https://docs.oracle.com/javase/8/docs/api/java/util/stream/Stream.html#reduce-U-java.util.function.BiFunction-java.util.function.BinaryOperator-)给出了精确定义。

不要用 `reduce(new ArrayList<>(), ...)` 原地修改列表累加结果；共享可变单位值不符合这种归约的使用要求。构建可变集合使用下一节的 `collect`。

## 十二、collect：收集到 List、Set、Map、数组和字符串

### 12.1 toList、toSet、toCollection

```java
List<String> names = users.stream()
        .map(User::getName)
        .collect(Collectors.toList());

Set<String> departments = users.stream()
        .map(User::getDepartment)
        .collect(Collectors.toSet());

ArrayList<String> arrayList = users.stream()
        .map(User::getName)
        .collect(Collectors.toCollection(ArrayList::new));

LinkedHashSet<String> orderedDepartments = users.stream()
        .map(User::getDepartment)
        .collect(Collectors.toCollection(LinkedHashSet::new));
// [研发, 测试, 产品]

TreeSet<String> sortedDepartments = users.stream()
        .map(User::getDepartment)
        .collect(Collectors.toCollection(TreeSet::new));
```

`toList()` 不承诺具体实现、可变性或线程安全；如果需要明确的可修改 ArrayList，就使用 `toCollection(ArrayList::new)`。`toSet()` 不承诺遍历顺序，需要顺序时选择 `LinkedHashSet` 或 `TreeSet`。TreeSet 按比较结果判重，比较为 0 的元素只保留一个。相关契约见 [Collectors 文档](https://docs.oracle.com/javase/8/docs/api/java/util/stream/Collectors.html)。

### 12.2 toMap：三种重载和重复 key

```java
// 两参数形式：要求映射后的 ID 不重复。
Map<Long, User> byId = users.stream()
        .collect(Collectors.toMap(User::getId, Function.identity()));

// 三参数形式：部门会重复，把同部门人数相加。
Map<String, Long> countByDepartment = users.stream()
        .collect(Collectors.toMap(User::getDepartment, u -> 1L, Long::sum));
// {研发=2, 测试=2, 产品=1}，默认 Map 的遍历顺序不保证。

// 四参数形式：指定 Map 工厂，并在 key 重复时保留先出现的值。
Map<String, User> firstByDepartment = users.stream()
        .collect(Collectors.toMap(
                User::getDepartment,
                Function.identity(),
                (first, later) -> first,
                LinkedHashMap::new
        ));
```

两参数版本遇到重复 key 会抛出 `IllegalStateException`。第三个参数不是可有可无的语法补丁，它表达“覆盖、保留、累加、取最大”等业务规则。

Java 8 的 `toMap` 不接受映射出的 null value；也不要依赖不同目标 Map 对 null key 的不同支持。应提前过滤、赋予有业务意义的默认值，或者改用显式循环构造能接受空值的 Map。

如果一个 key 对应多条完整记录，要使用 `groupingBy`，无需先手动拼 List。

### 12.3 toArray：对象数组与基本类型数组

```java
Object[] objects = users.stream().map(User::getName).toArray();
String[] names = users.stream().map(User::getName).toArray(String[]::new);
User[] userArray = users.stream().toArray(User[]::new);
int[] ages = users.stream().mapToInt(User::getAge).toArray();
```

直接 `toArray()` 返回 `Object[]`，不能强制转换成 `String[]`。需要具体数组类型时传入数组构造器。

### 12.4 joining：拼接字符串

```java
String csv = users.stream()
        .map(User::getName)
        .collect(Collectors.joining(","));
// 张三,李四,王五,赵六,孙七

String display = users.stream()
        .map(User::getName)
        .collect(Collectors.joining("、", "[", "]"));
// [张三、李四、王五、赵六、孙七]

String compact = Stream.of("J", "a", "v", "a")
        .collect(Collectors.joining()); // Java
```

`joining` 面向字符序列；数字可以先 `.map(String::valueOf)`。拼出的文本不自动执行 CSV 转义、SQL 参数化或 HTML 转义，应交给对应格式的工具处理。

### 12.5 collectingAndThen：收集后再转换

```java
List<String> readOnlyNames = users.stream()
        .map(User::getName)
        .collect(Collectors.collectingAndThen(
                Collectors.toList(),
                Collections::unmodifiableList
        ));
```

这个结果不允许通过 List 接口增删改；如果元素是可变对象，仍然可以修改对象内部状态。它也不会自动深拷贝元素。

### 12.6 三参数 collect 与 Collector.of

```java
ArrayList<String> names = users.stream().collect(
        ArrayList::new,
        (list, user) -> list.add(user.getName()),
        ArrayList::addAll
);

Collector<User, List<String>, List<String>> nameCollector = Collector.of(
        ArrayList<String>::new,
        (list, user) -> list.add(user.getName()),
        (left, right) -> {
            left.addAll(right);
            return left;
        }
);
List<String> customNames = users.parallelStream().collect(nameCollector);
```

supplier 每次都要返回新容器；accumulator 添加单个元素，combiner 合并部分容器。`Collector<T, A, R>` 中 T 是输入元素，A 是中间累积容器，R 是最终结果；还可以通过 finisher 把 A 转为 R。

不要随意声明 `CONCURRENT`、`UNORDERED` 或 `IDENTITY_FINISH` 特征。只有累积器能安全并发写入同一个容器时才适合 CONCURRENT；IDENTITY_FINISH 要求中间容器本身就可作为最终结果。常规业务优先组合现有 Collectors。

## 十三、groupingBy：分组与下游收集器

分组时，`groupingBy(classifier, downstream)` 先决定元素属于哪个 key，再让下游收集器处理该组的元素。理解这一点后，大部分报表统计都能组合出来。

### 13.1 按部门分组，指定 Map 实现

```java
Map<String, List<User>> grouped = users.stream()
        .collect(Collectors.groupingBy(User::getDepartment));
// 研发 -> 张三、李四；测试 -> 王五、孙七；产品 -> 赵六。

Map<String, List<User>> ordered = users.stream()
        .collect(Collectors.groupingBy(
                User::getDepartment,
                LinkedHashMap::new,
                Collectors.toList()
        ));
```

三种重载依次是：仅分类器、分类器加下游、分类器加 Map 工厂再加下游。默认不要依赖 Map 的遍历顺序，需要按 key 排序可以指定 `TreeMap::new`。null 分类结果应提前处理，例如将缺失部门映射为“未分配”，不要直接交给 `groupingBy`。

### 13.2 每组计数、求和、平均值和综合统计

```java
Map<String, Long> counts = users.stream()
        .collect(Collectors.groupingBy(
                User::getDepartment, Collectors.counting()));
// 研发=2，测试=2，产品=1

Map<String, Integer> ageTotals = users.stream()
        .collect(Collectors.groupingBy(
                User::getDepartment, Collectors.summingInt(User::getAge)));
// 研发=60，测试=52，产品=35

Map<String, Double> averageAges = users.stream()
        .collect(Collectors.groupingBy(
                User::getDepartment, Collectors.averagingInt(User::getAge)));
// 研发=30.0，测试=26.0，产品=35.0

Map<String, IntSummaryStatistics> ageStatistics = users.stream()
        .collect(Collectors.groupingBy(
                User::getDepartment, Collectors.summarizingInt(User::getAge)));
```

`summingInt/Long/Double`、`averagingInt/Long/Double`、`summarizingInt/Long/Double` 分别对应三个数值类型；规则与数值流类似。`counting()` 返回 Long，`averaging...` 返回 Double，`summarizing...` 返回对应的统计对象。

### 13.3 mapping：分组后只保留某个字段

```java
Map<String, List<String>> namesByDepartment = users.stream()
        .collect(Collectors.groupingBy(
                User::getDepartment,
                Collectors.mapping(User::getName, Collectors.toList())
        ));

Map<String, String> joinedNames = users.stream()
        .collect(Collectors.groupingBy(
                User::getDepartment,
                Collectors.mapping(User::getName, Collectors.joining("、"))
        ));
// 研发=张三、李四；测试=王五、孙七；产品=赵六
```

直接先 `.map(User::getName)` 会丢失部门字段；作为下游的 `mapping` 则在分类之后转换组内元素。

### 13.4 minBy、maxBy 和收集后解包

```java
Map<String, Optional<User>> highestPaidByDepartment = users.stream()
        .collect(Collectors.groupingBy(
                User::getDepartment,
                Collectors.maxBy(Comparator.comparing(User::getSalary))
        ));

Map<String, User> youngestByDepartment = users.stream()
        .collect(Collectors.groupingBy(
                User::getDepartment,
                Collectors.collectingAndThen(
                        Collectors.minBy(Comparator.comparingInt(User::getAge)),
                        opt -> opt.orElseThrow(IllegalStateException::new)
                )
        ));
```

这里每个分组都由实际元素创建，组内至少有一个人，因此可以解包。若前面还有可能清空组内数据的自定义逻辑，就必须重新考虑空结果。

### 13.5 reducing：组内 BigDecimal 求和

```java
Map<String, BigDecimal> salaryTotals = users.stream()
        .collect(Collectors.groupingBy(
                User::getDepartment,
                Collectors.reducing(
                        BigDecimal.ZERO,
                        User::getSalary,
                        BigDecimal::add
                )
        ));
// 研发=40000，测试=27000，产品=20000
```

`Collectors.reducing` 有三种形式：`reducing(op)` 返回 Optional；`reducing(identity, op)` 指定单位值；`reducing(identity, mapper, op)` 先映射再归约。它特别适合当作分组下游；单条流水线归约直接使用 `Stream.reduce` 通常更清楚。

### 13.6 多级分组

```java
Map<String, Map<Integer, List<User>>> byDepartmentAndAge = users.stream()
        .collect(Collectors.groupingBy(
                User::getDepartment,
                Collectors.groupingBy(User::getAge)
        ));
// 测试 -> 24 -> 王五；测试 -> 28 -> 孙七。
```

嵌套层数过多会让类型和调用都难读。需要多维报表时，可以定义具有正确 equals/hashCode 的组合 key 类，再做一次分组。

## 十四、partitioningBy：按真假拆成两组

```java
Map<Boolean, List<User>> partitions = users.stream()
        .collect(Collectors.partitioningBy(u -> u.getAge() >= 30));

List<User> atLeast30 = partitions.get(true); // 李四、赵六
List<User> under30 = partitions.get(false); // 张三、王五、孙七

Map<Boolean, Long> counts = users.stream()
        .collect(Collectors.partitioningBy(
                u -> u.getAge() >= 30,
                Collectors.counting()
        )); // true=2，false=3
```

`groupingBy` 的 key 可以有多个；`partitioningBy` 专门表达布尔分区，结果包含 true 和 false 两个 key，即使其中一边没有元素。用下游收集器时，空分区使用该收集器的空结果，例如 `counting()` 得到 0。

## 十五、遍历、调试与合并流

### 15.1 forEach 和 forEachOrdered

```java
users.stream().forEach(u -> System.out.println(u.getName()));

users.parallelStream()
        .forEachOrdered(u -> System.out.println(u.getName()));
// forEachOrdered 按 List 的遭遇顺序输出，但不承诺在主线程执行。
```

`forEach` 返回 void，是终止操作。并行流中的 `forEach` 不保证顺序；需要保留遭遇顺序时用 `forEachOrdered`，但排序后的有序输出不意味着上游计算也按同样顺序发生。

只是简单遍历时，`users.forEach(...)` 或增强 for 循环已经足够。要生成一个新列表时，使用 `map` 加 `collect`，不要为了装结果而对外部列表逐个 add。

### 15.2 peek：观察流水线中的元素

```java
List<String> names = users.stream()
        .filter(u -> u.getAge() >= 30)
        .peek(u -> System.out.println("过滤后：" + u.getName()))
        .map(User::getName)
        .collect(Collectors.toList());
```

`peek` 是中间操作，也受惰性和短路影响。不要把“每条记录必须更新状态、发送消息、写数据库”等业务动作放进去；这些动作需要明确的执行、异常和重试语义。调试时的日志顺序也可能受到并行处理影响。

### 15.3 concat：连接两个流

```java
List<String> merged = Stream.concat(
                Stream.of("Java", "SQL"),
                Stream.of("Docker", "Java")
        )
        .distinct()
        .collect(Collectors.toList()); // [Java, SQL, Docker]
```

两个源都有顺序时，先连接第一个的元素，再连接第二个。任一输入为并行流，连接结果也是并行流。连接后的流关闭时会关闭输入流。大量列表合并时，用 `lists.stream().flatMap(Collection::stream)`，避免建立过深的 concat 调用链。

## 十六、并行流：语义、收集器和适用范围

### 16.1 parallel、sequential 和 isParallel

```java
Stream<User> pipeline = users.stream().parallel();
System.out.println(pipeline.isParallel()); // true

long count = pipeline
        .filter(u -> u.getAge() >= 30)
        .sequential()
        .count(); // 最终按顺序模式执行
```

`parallelStream()` 直接创建并行流；`parallel()` 和 `sequential()` 改变流水线的执行模式。它们不是给局部步骤划定线程边界，最后设置的模式作用于整条流水线。

并行化适合数据量足够大、单元素计算成本较高、任务容易拆分且无共享可变状态的情况。少量元素、简单字段转换、数据库查询和 HTTP 请求不能假设一加 `parallelStream()` 就更快；应在实际环境测量吞吐、延迟和资源使用。

### 16.2 避免外部可变容器

下面的危险写法仅作反例，不应执行：

```text
List<String> result = new ArrayList<>();
users.parallelStream().forEach(u -> result.add(u.getName()));
```

多个线程同时向普通 ArrayList 写入可能导致数据丢失或异常。把容器交给收集器管理：

```java
List<String> result = users.parallelStream()
        .map(User::getName)
        .collect(Collectors.toList());
```

普通 `toList` 可以用于并行流，框架负责分段累积和合并，结果仍保留有序流水线的遭遇顺序。这不意味着最终返回的 List 适合多个线程随意修改。

### 16.3 groupingByConcurrent 和 toConcurrentMap

```java
ConcurrentMap<String, List<User>> grouped = users.parallelStream()
        .collect(Collectors.groupingByConcurrent(User::getDepartment));

ConcurrentMap<String, Long> counts = users.parallelStream()
        .collect(Collectors.groupingByConcurrent(
                User::getDepartment, Collectors.counting()));

ConcurrentMap<Long, String> namesById = users.parallelStream()
        .collect(Collectors.toConcurrentMap(User::getId, User::getName));

ConcurrentMap<String, Long> mergedCounts = users.parallelStream()
        .collect(Collectors.toConcurrentMap(
                User::getDepartment, u -> 1L, Long::sum));
```

`groupingByConcurrent` 提供与 groupingBy 对应的三类重载；`toConcurrentMap` 也提供两参数、带合并函数、带合并函数和 ConcurrentMap 工厂三个版本。工厂必须返回 ConcurrentMap，例如需要按 key 排序时可用 `ConcurrentSkipListMap::new`。

这些收集器不保留遭遇顺序，不应用 `(a, b) -> a` 来表达“保留原 List 的第一条”。外层 Map 支持并发，也不代表分组得到的内层 List 可以在返回后被多个线程安全地直接修改。

### 16.4 unordered 不是打乱列表

```java
Set<String> departments = users.parallelStream()
        .unordered()
        .map(User::getDepartment)
        .collect(Collectors.toSet());
```

`unordered()` 放弃遭遇顺序要求，不会主动洗牌。只有业务确实不关心顺序时才使用；它可能给 `distinct`、`limit` 等操作更多优化空间，也会改变“前几个”等结果的可选范围。

## 十七、BaseStream：迭代器、关闭与底层入口

### 17.1 iterator 和 spliterator

```java
Iterator<String> iterator = users.stream()
        .map(User::getName)
        .iterator();
while (iterator.hasNext()) {
    System.out.println(iterator.next());
}

Spliterator<User> spliterator = users.stream().spliterator();
spliterator.forEachRemaining(System.out::println);
```

这是把流交给手工遍历的入口，调用后不应再尝试把同一条流用于其他终止操作。`Spliterator` 还提供拆分和特征信息，通常在封装数据源时使用。

已有 Iterable 时，可以通过 `StreamSupport` 建立流：

```java
Iterable<User> iterable = users;
List<String> names = StreamSupport.stream(iterable.spliterator(), false)
        .map(User::getName)
        .collect(Collectors.toList());
// 第二个参数 false 表示顺序模式。
```

### 17.2 onClose 和 close

```java
try (Stream<User> stream = users.stream()
        .onClose(() -> System.out.println("流已关闭"))) {
    System.out.println(stream.count());
}
// 离开 try 块后执行关闭处理器。
```

终止操作不自动调用 `close()`。List 的内存流通常不需要显式关闭；`Files.lines(path)` 等持有 I/O 资源的流应使用 try-with-resources。`onClose` 只注册关闭处理器，真正 close 时才执行；多个处理器按注册顺序调用。参见 [BaseStream 文档](https://docs.oracle.com/javase/8/docs/api/java/util/stream/BaseStream.html)。

## 十八、业务中常用的组合写法

### 18.1 两个列表求交集、差集和并集

```java
List<Long> left = Arrays.asList(1L, 2L, 2L, 3L);
List<Long> right = Arrays.asList(2L, 3L, 4L);
Set<Long> rightSet = new HashSet<>(right);

List<Long> intersection = left.stream()
        .filter(rightSet::contains)
        .distinct()
        .collect(Collectors.toList()); // [2, 3]

List<Long> difference = left.stream()
        .filter(id -> !rightSet.contains(id))
        .distinct()
        .collect(Collectors.toList()); // [1]

List<Long> union = Stream.concat(left.stream(), right.stream())
        .distinct()
        .collect(Collectors.toList()); // [1, 2, 3, 4]
```

这里按集合语义去重，并保留首次出现顺序；如果需要保留左侧重复项，移除对应的 `distinct()`。把右侧转换成 HashSet，可避免对每个左元素都线性扫描一次右列表，通常把匹配开销从 O(n×m) 改善到期望 O(n+m)。

### 18.2 查出重复值和出现次数

```java
List<String> skills = Arrays.asList("Java", "SQL", "Java", "Docker", "SQL", "SQL");
Map<String, Long> frequency = skills.stream()
        .collect(Collectors.groupingBy(
                Function.identity(), LinkedHashMap::new, Collectors.counting()));

List<String> repeated = frequency.entrySet().stream()
        .filter(e -> e.getValue() > 1)
        .map(Map.Entry::getKey)
        .collect(Collectors.toList()); // [Java, SQL]
// frequency：Java=2，SQL=3，Docker=1
```

查重和去重是两件事：`distinct()` 给出去重后的值，不会告诉你哪些值曾重复。

### 18.3 每个部门取工资最高的两个人

```java
Map<String, List<User>> topTwoByDepartment = users.stream()
        .collect(Collectors.groupingBy(
                User::getDepartment,
                Collectors.collectingAndThen(
                        Collectors.toList(),
                        list -> list.stream()
                                .sorted(Comparator.comparing(User::getSalary)
                                        .reversed().thenComparing(User::getId))
                                .limit(2)
                                .collect(Collectors.toList())
                )
        ));
```

这会收集并排序每个分组，适合中小规模内存数据。数据量很大时，可考虑数据库窗口函数或维护有限大小的堆，避免完整保存和排序所有组内记录。

### 18.4 分组统计符合条件的人数，保留计数为 0 的部门

```java
Map<String, Long> age30Counts = users.stream()
        .collect(Collectors.groupingBy(
                User::getDepartment,
                Collectors.summingLong(u -> u.getAge() >= 30 ? 1L : 0L)
        ));
// 研发=1，测试=0，产品=1
```

若先 `.filter(u -> u.getAge() >= 30)` 再分组，测试部门会直接消失。Java 8 没有下游 `Collectors.filtering`，但条件计数可以用这种方式表达。完全没有出现在输入中的部门仍不会被自动补齐，需要结合完整部门列表处理。

### 18.5 关联查询：先建立索引，再做映射

```java
Map<Long, User> userIndex = users.stream()
        .collect(Collectors.toMap(User::getId, Function.identity()));

List<Long> requestedIds = Arrays.asList(2L, 99L, 1L);
List<String> requestedNames = requestedIds.stream()
        .map(userIndex::get)
        .filter(Objects::nonNull)
        .map(User::getName)
        .collect(Collectors.toList()); // [李四, 张三]
```

输出按请求 ID 的顺序排列，缺失 ID 在这里被跳过。需要保留缺失位置时，应返回带 ID 和匹配状态的 DTO。先建立索引也能避免每处理一条请求就完整扫描一次用户列表。

### 18.6 按多个字段分组，避免字符串拼接冲突

```java
Map<List<Object>, List<User>> byDepartmentAndAge = users.stream()
        .collect(Collectors.groupingBy(
                u -> Arrays.<Object>asList(u.getDepartment(), u.getAge())
        ));
```

这里借助 List 的按元素判等表示二元 key，比简单拼接 `department + age` 更不容易混淆边界。但 key 放入 Map 后不能修改；长期使用时建议定义不可变的 `DepartmentAgeKey` 类，明确字段类型和 equals/hashCode。

### 19.3 中间、终止和短路的区别

| 特征 | 例子 | 实际含义 |
| --- | --- | --- |
| 无状态中间操作 | `filter`、`map`、`flatMap`、`peek` | 处理当前元素通常不需要保存跨元素状态 |
| 有状态中间操作 | `distinct`、`sorted`、`limit`、`skip` | 需要记忆已见元素、排序数据或数量信息 |
| 短路中间操作 | `limit` | 某些流水线可在未读完源时结束 |
| 短路终止操作 | `findFirst`、`findAny`、三个 Match | 有可能提前决定结果 |
| 其他终止操作 | `collect`、`reduce`、`count`、`min`、`max`、`toArray`、遍历 | 消费流水线并产生结果或副作用 |

“短路”不保证任何输入都能迅速结束。例如，对无限流先过滤掉所有元素，再 `limit(1)`，永远收不到第一个结果；在 `limit` 之前对无限流排序，也无法完成。`sorted().limit(n)` 对有限集合能得到 Top N，但通常仍需读取并排序全部输入。

## 二十、容易踩坑的地方

1. **混用高版本 API。** Java 8 没有 `Stream.toList()`、`List.of()`、`Stream.ofNullable()`、`takeWhile()`、`dropWhile()`、`mapMulti()`，也没有 `Collectors.filtering/flatMapping/teeing`。收集列表用 `collect(Collectors.toList())`，集合常量可用 `Arrays.asList(...)`，不要直接复制高版本示例。
2. **把 Arrays.asList 当作普通 ArrayList。** 它是由数组支持的固定大小列表，不能直接 add/remove；需要增删时套一层 `new ArrayList<>(...)`。本文 sampleUsers 已这样处理。
3. **以为 Stream 会修改原列表。** `.sorted().collect(...)` 生成新的结果列表；要原地排序使用 `list.sort(comparator)`，要原地删除使用 `removeIf`，要原地替换使用 `replaceAll`。
4. **遍历期间增删源集合。** 在 `filter/forEach` 中对源 List 做结构修改，违反普通集合流的非干扰要求，可能出现 `ConcurrentModificationException` 或其他不可靠结果。需要修改时明确使用集合自身的修改 API。
5. **把 null 和空结果混为一谈。** List 为 null、元素为 null、属性为 null、查找没有结果，分别在不同层次处理；不能靠一个 `filter(Objects::nonNull)` 解决全部问题。
6. **依赖 Map、Set 默认顺序。** 要求顺序就选择对应容器，并确认收集器和流水线的顺序语义；并发收集器尤其不能承担“原列表第一条”的规则。
7. **用有副作用的 Lambda 隐藏业务动作。** 保存、通知、扣款等需要清晰控制流程。Stream 也没有事务或自动重试能力，执行到一半异常时，之前发生的副作用不会自动撤销。
8. **忽略异常处理。** `Integer.parseInt` 可能抛出 NumberFormatException；checked exception 也不能直接塞进不声明该异常的标准函数接口。应明确失败、包装异常或记录校验结果的策略，不能无声吞掉异常或用默认值掩盖坏数据。
9. **为了链式写法强行使用 Stream。** 复杂分支、需要 break/continue、多处状态更新时，普通循环往往更清楚。只取列表长度直接 `list.size()`，无需先建立流。
10. **没有测量就认定 Stream 更快。** 先过滤再昂贵映射、用 Set/Map 做索引、避免无用排序，往往比简单开启并行更有价值。只有当改变操作顺序不改变语义时，才可进行这些调整。

实际写一条流水线时，可以依次确认四件事：输入是否可能为空，处理后的元素是什么类型，是否需要保留顺序，最终需要什么结果。过滤选 `filter`，转换选 `map`，展开选 `flatMap`，组内统计组合下游 Collector；需要修改源数据时则回到集合自身的操作。
