配置生成脚本执行成功，服务却偶发报出 JSON 解析错误；把写入改成“临时文件加 mv”以后，异常减少了，但发布进程退出、机器重启或者两个发布任务同时运行时，结果仍然说不清楚。

这些问题来自不同的边界：文件内容写了一半、路径切换是否原子、数据是否持久化、消费者是否重新加载、多个发布者是否互相覆盖。本文只围绕 Linux 上一个 JSON 配置文件的发布，逐层建立可以复现、可以排错的操作流程。

## 一、应用场景、目标与适用范围

适用于小型服务配置、定期生成的路由清单、供多个进程读取的状态快照。读者需要了解文件路径、权限、Python 异常和 Shell 退出码。完成实验后，应能够：

1. 解释为什么直接覆盖文件会暴露空内容或半份内容。
2. 使用同目录临时文件实现一次完整快照的切换。
3. 区分“尚未发布”“已发布但持久化未确认”“已同步”三种结果。
4. 设计配置回退、消费者重载及并发发布规则。

**示例目标环境：Linux、本地文件系统、Python 3.11 或更高版本、Bash。** 示例按 Python 3.14 官方 API 及 Linux man-pages 核对；不依赖第三方 Python 包。本文不使用 renameat2 等扩展标志。

实际验证环境：macOS 26.7.1 arm64 宿主上的 OrbStack，Linux 7.2.12 aarch64，Debian 13.7 容器，CPython 3.14.10。主实验目录位于容器 overlayfs；跨挂载实验使用 /dev/shm 的 tmpfs。运行身份为 UID/GID 65534，容器无网络、无宿主目录挂载，退出后删除。

这验证了程序行为和错误分支，**没有验证断电恢复、物理存储写缓存、独立 ext4/XFS、NFS/CIFS、SELinux 生产策略或真实服务重载**。尤其不能用 overlayfs 上一次 fsync 成功证明整条虚拟化和硬件存储链已经通过断电测试。Python 3.11/3.12 运行时也未单独实测。

本文只操作新建实验目录，普通用户权限即可。生产目录必须由可信主体控制，发布期间父目录及其祖先不能被其他进程替换；目标不是符号链接，消费者不原地修改已发布文件。本文程序不是在恶意用户可写目录里工作的安全文件服务。

## 二、先分清四个不同的保证

### 2.1 内容完整：直接覆盖会先破坏旧快照

用写模式打开既有文件通常会先截断它；之后才逐步写入内容。读进程如果正好在两者之间打开文件，可能看到空文件或不完整 JSON。写入进程的用户态缓冲又会扩大“应用已经调用 write，但其他进程尚看不到全部内容”的差异。

所以“写完后运行 JSON 校验”太晚了：校验失败时，旧的可用配置已经被破坏。正确顺序是先准备候选内容、校验，再发布。

### 2.2 可见性原子：切换目录项，不原地改旧文件

临时文件准备好以后，在同一目录执行 rename 替换目标名称。对既有目标，成功的替换没有“目标名称暂时不存在”的窗口；已经打开旧文件的描述符仍指向旧对象。跨挂载会遇到 EXDEV，不能用复制覆盖来维持相同的原子性承诺。[Linux rename(2)](https://man7.org/linux/man-pages/man2/rename.2.html)

这里的完整快照还依赖应用约束：发布以后不能再修改那个 inode；读取一份配置时只打开一次并从同一描述符读取。先按路径读取 version、关闭，再重新打开读取 endpoint，两个字段可能跨越两次发布。

### 2.3 持久化：flush、文件 fsync、目录 fsync 各有职责

本例采用以下顺序：

```text
读取并校验候选内容
  → 在目标目录安全创建临时文件
  → 写入完整内容、flush、设置权限
  → fsync 临时文件
  → replace 临时文件到目标名称
  → fsync 目标目录
  → 报告发布与同步完成
```

Python 的 flush 先把用户态缓冲交给操作系统；fsync 文件后，还要同步包含名称变化的目录。Linux 文档明确区分文件同步和目录项同步，并列出 EIO、ENOSPC 等同步失败。[Linux fsync(2)](https://man7.org/linux/man-pages/man2/fsync.2.html) Python 缓冲文件的调用顺序见 [os.fsync](https://docs.python.org/3.14/library/os.html#os.fsync)。

目录本身应当已经可靠存在。本例不会递归创建生产目录，也不负责把刚创建的父目录逐层同步。

### 2.4 应用生效：文件换了，服务可能仍用旧配置

服务可能长期持有旧描述符，也可能已经把配置解析为内存对象。文件发布完成，不代表服务配置已经生效。消费者应在重载时重新打开、完整读取和校验，构造新对象后再切换内存引用；校验失败时保留上一份内存配置。

本例没有自动发送信号或重启服务。生产重载必须使用服务自己的官方接口，并核对其实际加载版本。

## 三、准备一个独立实验目录

以下 Shell 块适用于 Linux/Bash，以当前用户执行，无需 sudo。将后续两份 Python 文件保存在该目录。所有覆盖和删除仅限这里。

```bash

```

umask 077 限制新建文件的默认权限，mktemp -d 创建独立目录。old.json 是本实验保留的已知可用版本；candidate.json 是要发布的候选。不要把路径改成生产配置后直接照抄后文故障实验。

## 四、完整的原子发布程序

保存为 atomic_config.py：

```python
import argparse
import json
import os
from pathlib import Path
import stat
import sys
import tempfile

MAX_BYTES = 1024 * 1024


class PublishedButNotDurable(RuntimeError):
    pass


def no_duplicates(pairs):
    result = {}
    for key, value in pairs:
        if key in result:
            raise ValueError("duplicate key: " + key)
        result[key] = value
    return result


def validate(data):
    if len(data) > MAX_BYTES:
        raise ValueError("configuration exceeds 1 MiB")
    obj = json.loads(data.decode("utf-8"), object_pairs_hook=no_duplicates)
    if type(obj) is not dict or set(obj) != {"version", "endpoint"}:
        raise ValueError("expected exactly version and endpoint")
    if type(obj["version"]) is not int or obj["version"] < 1:
        raise ValueError("version must be a positive integer")
    if type(obj["endpoint"]) is not str or not obj["endpoint"].startswith("https://"):
        raise ValueError("endpoint must start with https://")
    return obj


def publish(target, data):
    validate(data)
    target = Path(target).absolute()
    # Precondition: parent and its ancestors are trusted, stable directories.
    try:
        if not stat.S_ISREG(target.lstat().st_mode):
            raise ValueError("target must be a regular file, not a symlink")
    except FileNotFoundError:
        pass
    directory_fd = os.open(target.parent, os.O_RDONLY | os.O_DIRECTORY)
    temporary = None
    published = False
    try:
        fd, temporary = tempfile.mkstemp(prefix="." + target.name + ".", dir=target.parent)
        with os.fdopen(fd, "wb") as stream:
            stream.write(data)
            stream.flush()
            os.fchmod(stream.fileno(), 0o600)
            os.fsync(stream.fileno())
        os.replace(temporary, target)
        published = True
        temporary = None
        os.fsync(directory_fd)
    except Exception as exc:
        if published:
            raise PublishedButNotDurable(
                "replacement is visible; directory durability is unconfirmed"
            ) from exc
        raise
    finally:
        try:
            if temporary is not None:
                os.unlink(temporary)
        finally:
            os.close(directory_fd)


def main():
    parser = argparse.ArgumentParser()
    parser.add_argument("candidate")
    parser.add_argument("target")
    args = parser.parse_args()
    try:
        with open(args.candidate, "rb") as stream:
            data = stream.read(MAX_BYTES + 1)
        publish(args.target, data)
    except PublishedButNotDurable as exc:
        print("PUBLISHED_UNCONFIRMED: " + str(exc), file=sys.stderr)
        return 3
    except (OSError, ValueError) as exc:
        print("NOT_PUBLISHED: " + str(exc), file=sys.stderr)
        return 2
    print("PUBLISHED_AND_SYNCED")
    return 0


if __name__ == "__main__":
    sys.exit(main())
```

### 4.1 为什么这样实现

| 设计点 | 用途与限制 |
| --- | --- |
| 候选最多读取 1 MiB 加 1 字节 | 发现超限即可拒绝，避免 CLI 无上限读取；publish 函数的调用方仍需自行控制输入分配 |
| 精确检查字段、拒绝重复键和布尔 version | 避免配置拼错或 Python 中 bool 属于 int 子类带来的歧义 |
| endpoint 只检查 https 前缀 | 这是演示配置校验，不是 URL 安全策略；真实客户端还需校验主机、端口及访问范围 |
| mkstemp 指定目标父目录 | 排他创建唯一临时文件，避免固定 .tmp 名称冲突，也避免默认临时目录位于另一挂载 |
| 文件权限固定为 0600 | 只允许文件拥有者读写；发布者和消费者应使用同一 UID，或先按实际权限模型改造程序 |
| 显式调用 os.replace | 替换语义清楚，不加入跨文件系统复制的退路 |
| 替换后目录同步失败单独报告 | 此时新内容已经可见，不能仍报告“旧配置未动” |

安全创建与手工清理要求见 [tempfile.mkstemp](https://docs.python.org/3.14/library/tempfile.html#tempfile.mkstemp)，替换语义见 [os.replace](https://docs.python.org/3.14/library/os.html#os.replace)。mkstemp 返回的描述符交给 fdopen 管理；正常退出以及普通错误分支会关闭它并清理尚未发布的临时名称。

**新文件不会继承旧文件的全部属性。** 本例生成新的 inode，固定为 0600，拥有者是发布进程，组受创建目录规则影响；不承诺保留原 ACL、扩展属性、SELinux 标签或硬链接关系。生产需要在替换前完成并验证元数据准备；有强制访问控制时，必须按实际策略测试，不能通过放宽成 0777 解决读取失败。

对目标 lstat 的检查依赖可信、稳定目录的前提，不是抵御路径竞争攻击的充分手段。若其他主体可以修改父目录，需重新设计目录描述符相对操作、路径解析策略及授权模型，不能只补一个 exists 检查。

### 4.2 正常发布与检查

```bash
python3 atomic_config.py old.json app.json
python3 atomic_config.py candidate.json app.json
python3 -m json.tool app.json
stat -c 'inode=%i mode=%a owner=%u group=%g' app.json
```

前两条均应输出 PUBLISHED_AND_SYNCED；json.tool 应显示 version 为 2、endpoint 为 https://new.example；mode 应为 600。inode、UID、GID 的具体数字因环境而异。

CLI 的返回值约定如下，前提是本地受支持文件系统、目录可信且没有其他发布者干扰：

| 退出码 | 含义 | 调用方动作 |
| --- | --- | --- |
| 0 | 替换与两次同步均成功返回 | 继续执行服务重载与健康验证 |
| 2 | 替换前的校验、创建、写入或同步失败，或 replace 自身报错 | 保留旧版运行，检查 stderr、目标实际内容及清理状态 |
| 3 | replace 已返回成功，后续目录同步失败 | 按已可见处理；核对版本和存储故障，不能假定旧版仍在 |
| 被信号终止、会话断开等 | 没有可信的最终结果 | 重新连接后核对实际文件和服务版本，再决定后续动作 |

异常清理本身若失败，应保留原始错误上下文并人工检查；不能仅凭通用非零退出码推断磁盘状态。NFS 还存在“rename 报错但服务端实际已完成”的特殊边界，本文状态分类不推广到网络文件系统，详见 rename(2) 的 BUGS。

验证候选失败后，确认目标仍为版本 2：

```bash
printf '%s\n' '{' > broken.json
publish_rc=0
python3 atomic_config.py broken.json app.json || publish_rc=$?
test "$publish_rc" -eq 2
python3 -c 'import json; assert json.load(open("app.json"))["version"] == 2'
```

预期 stderr 以 NOT_PUBLISHED 开头，两个检查返回 0。这里显式捕获状态码，也能在启用 set -e 的 Bash 中继续执行检查。

## 五、九项可复现实验：观察边界，而不是依赖 sleep

将下面文件保存为 verify_atomic.py，与发布程序放在同一目录。它只在自身创建的临时目录中运行；第九项需要可写的 /dev/shm，且与 /tmp 属于不同设备。没有这一条件时应改用两个独立可写挂载点，并重新确认路径；不要把失败当成发布程序出错。

第 1 项在写到一半时主动读取，确定性复现坏快照；第 4、5、6 项通过 mock 注入 API 错误，不制造磁盘故障。第 8 项是有界并发正确性检查，不是吞吐测试，也不保证每次调度都覆盖所有交错。

```python
import errno
import json
import os
from pathlib import Path
import stat
import tempfile
import threading
from unittest.mock import patch

import atomic_config as ac


def check(condition, message):
    if not condition:
        raise AssertionError(message)


def must_raise(kind, action):
    try:
        action()
    except kind:
        return
    raise AssertionError("expected " + kind.__name__)


old = b'{"version":1,"endpoint":"https://old.example"}\n'
new = b'{"version":2,"endpoint":"https://new.example"}\n'

with tempfile.TemporaryDirectory(prefix="atomic-check-") as root:
    target = Path(root) / "app.json"
    ac.publish(target, old)

    # Deterministically pause an in-place writer after only its first fragment.
    with open(target, "wb") as writer:
        writer.write(b'{"version":')
        writer.flush()
        must_raise(json.JSONDecodeError, lambda: json.loads(target.read_bytes()))
    print("PASS 1: in-place write exposes incomplete JSON")

    ac.publish(target, old)
    with open(target, "rb") as held:
        inode = os.fstat(held.fileno()).st_ino
        ac.publish(target, new)
        check(held.read() == old, "old descriptor changed")
        check(target.read_bytes() == new, "new open did not see new content")
        check(inode != target.stat().st_ino, "inode did not change")
    print("PASS 2: held descriptor sees old; new open sees new")

    for bad in (b'{', b'{"version":true,"endpoint":"https://a"}',
                b'{"version":1,"version":2,"endpoint":"https://a"}'):
        must_raise(ValueError, lambda: ac.publish(target, bad))
        check(target.read_bytes() == new, "invalid candidate replaced target")
    print("PASS 3: malformed, boolean version and duplicate key rejected")

    with patch.object(ac.os, "fsync", side_effect=OSError(errno.EIO, "injected file sync")):
        must_raise(OSError, lambda: ac.publish(target, old))
    check(target.read_bytes() == new, "file-sync failure replaced target")
    print("PASS 4: file fsync failure keeps old target")

    with patch.object(ac.os, "replace", side_effect=OSError(errno.EACCES, "injected rename")):
        must_raise(OSError, lambda: ac.publish(target, old))
    check(target.read_bytes() == new, "rename failure replaced target")
    print("PASS 5: rename failure keeps old target")

    real_fsync = ac.os.fsync

    def fail_directory(fd):
        if stat.S_ISDIR(os.fstat(fd).st_mode):
            raise OSError(errno.EIO, "injected directory sync")
        return real_fsync(fd)

    with patch.object(ac.os, "fsync", side_effect=fail_directory):
        must_raise(ac.PublishedButNotDurable, lambda: ac.publish(target, old))
    check(target.read_bytes() == old, "published state was lost")
    print("PASS 6: directory fsync failure reports visible replacement")

    ac.publish(target, new)
    check(stat.S_IMODE(target.stat().st_mode) == 0o600, "wrong mode")
    check(not list(Path(root).glob(".app.json.*")), "temporary file leaked")
    link = Path(root) / "link.json"
    link.symlink_to(target)
    must_raise(ValueError, lambda: ac.publish(link, old))
    check(target.read_bytes() == new, "symlink referent modified")
    print("PASS 7: mode, cleanup and symlink rejection verified")

    # Each reader opens once per snapshot. A barrier ensures both readers start.
    barrier = threading.Barrier(3)
    failures = []

    def reader():
        try:
            barrier.wait(timeout=10)
            for _ in range(1000):
                check(target.read_bytes() in (old, new), "torn or missing snapshot")
        except BaseException as exc:
            failures.append(exc)

    readers = [threading.Thread(target=reader) for _ in range(2)]
    for thread in readers:
        thread.start()
    barrier.wait(timeout=10)
    for i in range(100):
        ac.publish(target, old if i % 2 == 0 else new)
    for thread in readers:
        thread.join(timeout=10)
        check(not thread.is_alive(), "reader timed out")
    check(not failures, repr(failures))
    print("PASS 8: 2000 reader snapshots across 100 publications")

    # Requires a different writable mount; no copy-and-delete fallback is used.
    check(os.stat(root).st_dev != os.stat("/dev/shm").st_dev, "need separate mount")
    with tempfile.TemporaryDirectory(dir="/dev/shm", prefix="atomic-cross-") as other:
        source = Path(other) / "candidate.json"
        source.write_bytes(old)
        try:
            os.replace(source, target)
        except OSError as exc:
            check(exc.errno == errno.EXDEV, repr(exc))
        else:
            raise AssertionError("expected EXDEV")
        check(source.exists() and target.read_bytes() == new, "cross-mount data changed")
    print("PASS 9: cross-mount replace returns EXDEV without copying")

print("ALL 9 CASES PASSED")
```

运行：

```bash

```

本次实际输出：

```text

PASS 2: held descriptor sees old; new open sees new
PASS 3: malformed, boolean version and duplicate key rejected
PASS 4: file fsync failure keeps old target
PASS 5: rename failure keeps old target
PASS 6: directory fsync failure reports visible replacement
PASS 7: mode, cleanup and symlink rejection verified
PASS 8: 2000 reader snapshots across 100 publications
PASS 9: cross-mount replace returns EXDEV without copying
ALL 9 CASES PASSED
```

第 2 项尤其关键：held 描述符读到旧内容不表示发布失败，而是打开文件与路径名称的生命周期不同。第 6 项证明为什么不能在任何异常后都说“本次完全没改文件”。第 9 项直接使用 os.replace，不做复制，因此保留了跨挂载失败的明确边界。

## 六、从文件切换走向可恢复的发布流程

### 6.1 两个发布者不会写出半份 JSON，但仍可能丢更新

发布者 A、B 各自准备完整候选，最后一次成功 replace 决定路径上的版本。即使两个程序都返回 0，A 也不能据此认为自己的版本仍是当前版本。字段 version 在本例中仅用于观察，不负责比较并交换；较低版本完全可能覆盖较高版本。

需要串行化时，对一个独立、稳定的锁文件持锁，覆盖“读取当前版本、生成候选、校验、发布、必要的重载协调”整个业务临界区。不要把锁加在 app.json 本身，新旧 inode 会让不同发布者锁住不同对象。锁文件生命周期可参考本站 [Linux flock 实战](/pages/1e12c0/)。跨主机发布应使用真正的协调服务或具备事务/条件更新能力的存储。

如果候选是基于旧配置生成的，锁必须从读取旧版以前开始；只锁最后一条 rename 不能防止基于过期内容计算的覆盖。

### 6.2 进程在不同位置退出，恢复方式不同

| 中断阶段 | 正在运行的系统通常能观察到什么 | 恢复关注点 |
| --- | --- | --- |
| 临时文件尚未完成 | 旧目标；可能遗留临时文件 | 核对没有活跃发布者，再按明确文件清单清理 |
| 临时文件已同步，尚未替换 | 旧目标和一份候选临时文件 | 核对候选版本，不自动把遗留文件当成已批准版本 |
| 已替换，目录同步未确认 | 新目标已可见 | 重读当前内容、检查错误、核对消费者；重启后的结果还需存储层验证 |
| 同步完成，服务未重载 | 磁盘文件新、服务内存旧 | 重试服务自己的幂等重载流程并验证加载版本 |

SIGKILL 不执行 Python finally，因此临时文件可能残留。清理器不能只按文件年龄盲删，也不能删除其他正在进行的发布所用文件。本文命名规则只帮助识别，不提供发布者存活证明。

“进程被杀死”与“机器断电”不同。前者内核仍运行，后者涉及文件系统日志、写缓存、虚拟化和设备持久性。故障注入测试只能证明状态处理分支，不能替代断电恢复实验。

### 6.3 回退也是一次新发布

本例保留了 old.json。确认当前版本不可用且没有其他发布者后，可在实验目录执行：

```bash
python3 atomic_config.py old.json app.json
python3 -c 'import json; assert json.load(open("app.json"))["version"] == 1'
```

这会覆盖当前 app.json，恢复版本 1，影响后续重新打开文件的读者；已有内存配置仍需重载。old.json 必须是事先保留、校验且有权限保护的已知可用版本。不要先删除目标再复制备份，那会重新引入路径缺失或半写窗口。

生产回退应记录发布 ID、候选摘要、旧版本、新版本、实际加载结果。摘要是内容身份，不是保密措施；含密钥的候选和备份需要同等访问控制。重载失败后是否自动回退由业务策略决定，需避免与后来发布的正确版本竞争。

### 6.4 多文件不能直接套用一次单文件结论

依次替换 config.json 和 certificate.pem，中间可能让消费者读到两个不同版本。可以把相关文件放进不可变版本目录，以一个清单或指针选择版本，并让消费者先确定版本再从同一版本目录读取；具体设计仍需处理目录持久化、旧版本保留和引用生命周期。逐个 rename 不提供跨文件事务。

## 七、常见故障与定位顺序

| 现象 | 首先检查 | 处理方向 |
| --- | --- | --- |
| EXDEV / Invalid cross-device link | 临时文件是否建在 /tmp，而目标在另一挂载 | 在目标目录创建临时文件；本例已经这样做 |
| EACCES / Permission denied | 父目录访问、写权限与文件拥有者 | 使用最小权限的专用发布身份；目标文件可写不代表目录可替换 |
| 读服务报权限错误 | 新文件的 0600、UID/GID、ACL 和安全标签 | 在替换前准备实际权限模型，不在发布后临时补权限 |
| EROFS | 容器配置挂载、只读根目录、实际挂载点 | 改用受支持的可写状态目录；不要盲目重新挂载生产文件系统 |
| ENOSPC / EDQUOT | 可用空间、inode、用户配额 | 预留新旧文件同时存在的容量；排查后重试，不能忽略同步错误 |
| EIO 或目录 fsync 不支持 | stderr、底层文件系统及存储日志 | 保留错误、核对实际版本；不要删掉 fsync 让脚本“变成功” |
| 发布成功但服务行为没变 | 服务是否重新打开、缓存配置及实际加载版本 | 走服务官方重载与健康验证流程 |
| 偶尔版本倒退 | 是否有多个发布入口、过期候选及自动回退任务 | 统一协调，覆盖生成到加载的业务临界区 |

Linux 上可在实验目录运行以下只读诊断；没有 sudo，不会改权限、挂载或文件内容：

```bash
id
ls -ld .
ls -l app.json
stat -c 'device=%d inode=%i mode=%a uid=%u gid=%g' app.json
stat -f -c 'filesystem=%T' .
df -h .
df -i .
```

目录需要搜索权限；本文还以只读方式打开目录进行同步，因此发布身份也需要相应目录读取权限。绑定挂载到单个文件的容器配置、Kubernetes 投射卷等有额外生命周期约束，应按平台机制发布，不能假定它们就是普通可替换目录项。

## 八、性能、安全与跨平台差异

每次发布同步文件和目录会增加存储等待；高频状态不应不加分析地改成每条事件一次同步。可以合并快照、降低发布频率或使用数据库，但必须把可能丢失的窗口写进业务约定。本文没有测量或提供吞吐、时延数据。

旧文件仍被打开时，其存储可能继续占用；需要为旧版、新版、备份和遗留临时文件预留空间。原子替换也不会保留目标旧 inode 的硬链接别名，别名读者可能一直看到旧内容。

CLI 限制输入长度并不意味着允许读取任意候选路径：FIFO、设备、远程挂载都可能阻塞，生产调用方应提供已完成的普通文件或受限的 bytes 数据。不要把尚在写入的候选当作不可变输入；必要时校验签名、摘要和发布来源。不要在日志中输出密钥。

本文代码和测试以 Linux 为目标。macOS 没有 /dev/shm，不能直接执行第九项；GNU stat -c/-f -c 也不是 macOS BSD stat 的相同接口。macOS 查看普通文件属性可改为 stat -f '%i %Lp %u %g' app.json。涉及目录同步和存储持久性时必须重新核对系统接口和实际文件系统，本文不据 Linux 实验声明 macOS 具有完全相同的断电保证。Windows 的打开文件共享与替换约束也不在本文验证范围内。

实验完成后，先确认 atomic_lab 指向第三节创建的目录且不再需要其中内容，再执行以下 Bash 清理；它会永久删除整个实验目录及实验文件，恢复方法是重新创建目录并保存正文代码，不能用于生产路径：

```bash
cd /tmp
case "$atomic_lab" in
  /tmp/atomic-config.*) rm -rf -- "$atomic_lab" ;;
  *) printf '%s\n' 'unexpected path; cleanup refused' >&2 ;;
esac
unset atomic_lab
```

## 九、实际验证记录与实践要点

2026/11/19，在第一节列出的 Linux 容器内，两份 Python 代码原样运行，九组检查全部通过；2000 次读取快照未出现集合外内容，100 次发布全部完成。这是本次有界测试结果，不是对所有调度和文件系统的穷尽证明。正常发布、无效候选退出码、回退及只读诊断命令另行核对；断电和真实服务生效均未实测。

一个可靠的单文件发布流程，需要把校验、同目录暂存、完整写入、权限准备、文件同步、路径替换、目录同步、消费者重载及健康确认连接起来。原子替换解决路径切换问题；并发控制解决覆盖问题；恢复记录解决结果不确定问题。先写清每一步成功意味着什么，再让脚本按这个含义返回状态，才能在故障时作出正确判断。
